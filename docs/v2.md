# Go binding migration to Carve 0.2

The 0.2 binding is `github.com/markup-carve/carve-go/v2`. The root package remains the 0.1 binding. Pin a commit on this repository's `next2` branch when testing 0.2; nothing is published yet. The 0.2 package embeds the `carve2 call` WASI binary built from the carve-rs commit in `v2/internal/wasm/REV`. No registry version is involved.

## Render and options

| 0.1 root package | 0.2 package |
| --- | --- |
| `ToHTML`, `ToHTMLOptions` | Same helper names in `v2`, backed by `renderWithDiagnostics` |
| `Render(source, target, opts)` | Same call shape and named writer targets |
| `Options.Safe: true` | The 0.2 default has `rawHtml: false` and a denying URL policy. Use `Options.RawHTML: true` only for trusted source. |
| `Options.Static: true` | `Options.Mode: "static"` |
| `Options.Profile` | Same field, validated by the 0.2 engine |
| `Options.Symbols` | Same field, sent as the 0.2 `symbols` map |
| `Options.Extensions` | Retained. A nonempty list returns an unavailable error while the 0.2 extension host is pending. |
| `Options.AlignTables` | `Format(ctx, source, true)` once the Carve writer registers |
| `RenderChecked` and loss report | `RenderWithDiagnostics`; losses are diagnostic entries with `channel: "render-loss"` and UTF-8 byte ranges. Set `Options.StrictLosses` to refuse losses. |

`Options.URLPolicy` selects an allow or deny list of URL schemes. It does not weaken the secure default unless the caller explicitly supplies a policy. `HeadingIDs`, `Roundtrip`, and `SourceLines` map to the names in the 0.2 option catalog. The JSON boundary validates enum values and rule names. `Call` exposes other public 0.2 tooling calls while typed helpers are added.

## Tree, lint, includes, and imports

| 0.1 root package | 0.2 package |
| --- | --- |
| `ParseAST` | Same helper, returning a 2.0 tree; `Parse` also returns diagnostics. `RenderTree`, `EncodeTree`, `DecodeTree`, and `ValidateTree` operate on that tree. Positions and diagnostic ranges are UTF-8 byte offsets. |
| `LintWithOptions` with `Bundle` and `CaptionHints` | `Lint(ctx, source, LintOptions{Rules, Platforms, Include})`. Rules use the 0.2 rule catalog and values `on` or `off`. |
| `RenderWithIncludes(source, target, opts, inc)` | Same call shape, with `RenderWithIncludesContext` for cancellation. `Include` still carries an absolute root and source path. The result has diagnostics and dependencies. `IncludeDependencies` reads dependencies from a tree. |
| `FromHTML` | Same entry point, currently unavailable while `importDocument` is pending in the engine. |
| `FromMarkdown` | Same entry point, unavailable because Markdown import is outside core 0.2. |
| `DecisionTrace`, stamp calls, and `SelectIncludeRegion` | No 0.2 counterpart. The 0.2 upgrade tool in carve-js handles source migration. |

The 0.2 WASI include resolver currently refuses a mounted root. `RenderWithIncludes` reports that gap clearly; the engine issue is [carve-rs#4326](https://github.com/markup-carve/carve-rs/issues/4326). This also affects Hugo until the engine fix is pinned here. The writer and importer gaps are [carve-rs#4327](https://github.com/markup-carve/carve-rs/issues/4327) and [carve-rs#4328](https://github.com/markup-carve/carve-rs/issues/4328). Extension registration is [carve-rs#4329](https://github.com/markup-carve/carve-rs/issues/4329).

## Building the pinned engine

In a clean carve-rs checkout at the recorded `next2` commit, with `wasm32-wasip1` installed:

```sh
CARVE_RS=/path/to/carve-rs ./v2/build-wasm.sh
```

The script writes the WASI binary, the exact revision, and its checksum together. CI checks that the revision is an ancestor of carve-rs `next2` and that the artifact matches its checksum. The binary is embedded, so a user of the Go package needs no Rust toolchain.
